# Налаштування та перевірка — BookSpace

## 1. Що потрібно

| Інструмент | Для чого потрібен |
| --- | --- |
| Комп'ютер або ноутбук | Перегляд матеріалів |
| Браузер (Chrome, Firefox, Edge тощо) | Відкриття репозиторію GitHub |
| Інтернет | Доступ до GitHub |
| Обліковий запис GitHub | Потрібен для створення власного репозиторію та завантаження файлів |
| Git (необов'язково) | Клонування репозиторію на комп'ютер |

## 2. Розміщення проєкту на GitHub

1. Увійдіть на [github.com](https://github.com/).
2. Натисніть **New repository**.
3. Вкажіть назву `documentation-lab-kostiuchenko`.
4. Оберіть **Public**, а потім натисніть **Create repository**.
5. Розпакуйте ZIP-архів із лабораторною роботою.
6. У репозиторії натисніть **Add file → Upload files** та завантажте п'ять `.md` файлів і папку `images` з її вмістом, зберігши структуру каталогів.
7. Натисніть **Commit changes**.

> Якщо GitHub не дозволяє перетягнути папку, створіть папку `images` у репозиторії та окремо завантажте в неї файл `catalog-preview.png`.

## 3. Як відкрити документацію

1. Перейдіть у створений репозиторій.
2. На головній сторінці GitHub автоматично відобразиться `README.md`.
3. Відкрийте `USER_GUIDE.md`, `SETUP_GUIDE.md`, `API_OVERVIEW.md` і `CHANGELOG.md` через список файлів.
4. Щоб побачити макет, перегляньте ілюстрацію в `README.md` або відкрийте `images/catalog-preview.png`.

**Альтернативний спосіб (за наявності Git):**

```bash
git clone https://github.com/USERNAME/documentation-lab-kostiuchenko.git
cd documentation-lab-kostiuchenko
```

Замініть `USERNAME` на свій логін GitHub. Після клонування Markdown-файли можна відкрити у VS Code або іншому редакторі.

## 4. Перевірка роботи

Оскільки це навчальний **макет**, перевіряємо не роботу вебсервера, а правильність оформлення документації:

- [ ] У корені репозиторію є всі п'ять `.md` файлів.
- [ ] Заголовки, списки, таблиці та JSON-приклади відображаються правильно.
- [ ] Посилання між файлами відкривають потрібні документи.
- [ ] Зображення `images/catalog-preview.png` видно в `README.md` і `USER_GUIDE.md`.
- [ ] Файли можна переглянути без завантаження додаткових програм.

**Очікуваний результат:** GitHub показує структуру та вміст документації без помилок. Сам вебзастосунок не запускається, оскільки його програмна реалізація не входить до лабораторної.

## 5. Як виглядав би запуск готового продукту

Для майбутньої реалізації BookSpace передбачено: розміщення вебзастосунку на сервері, відкриття його адреси у браузері та перевірку, що каталог, пошук і жанрові фільтри реагують на дії користувача. Ці кроки описують план, а не вже доступну функціональність.
